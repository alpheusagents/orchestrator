# OpenCode V2 Reference

OpenCode V2 (`2.0.4+`) uses the `subagent` tool and the plural `agents` config. It is not the V1 `task` / `agent` schema.

This reference supports the `orchestrator-adapter-opencode` adapter. The adapter's `Dispatch Mapping` is authoritative for host targets; its `Permissions` section is recommended setup and the user applies it. This page covers that setup, built-in agents, resume caveats, and command registration. The orchestrator never edits host configuration.

## Agent configuration

Recommended; the user applies it.

- Define role agents under `agents` in `opencode.json` or `opencode.jsonc`.
- Alternatively, use Markdown agents under `.opencode/agents/<name>.md` (project) or `~/.config/opencode/agents/<name>.md` (global).
- Recommend `mode: "subagent"` explicitly. New custom agents default to `primary`; without `mode`, the agent may not be available as a subagent.
- Recommend pinning `model` on the role agent.

## Built-in agents

- `explore` is built-in and read-only. It reads code and web sources.
- `general` is built-in and can write and execute, but cannot launch more subagents.
- V2 has no built-in `scout`.

## Resume caveats

- Check `opencode --version` and the available tool names before dispatching.
- A subagent that fails or is closed may not resume. The adapter's `Resume` section defines the fallback.

## Command registration

- Recommended: create `.opencode/commands/orchestrate.md`.
- Let the command load the orchestrator skill and pass the task or plan path as `$ARGUMENTS`.
- Do not invent a command schema; use the current OpenCode documentation.

## No config sample

This page intentionally contains no `opencode.jsonc` sample; the host schema changes. Use the official OpenCode documentation for the current syntax.
